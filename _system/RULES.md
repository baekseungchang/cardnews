# 카드뉴스 제작 규칙 (v2, 2026-10-06)

이 파일이 카드뉴스 제작의 기준이다. 매일 작업 전에 처음부터 끝까지 읽고 그대로 따른다.
가장 중요한 것은 **정확성**이다. 틀린 문장 1개가 카드 전체의 신뢰를 무너뜨린다.

## 2. 리서치: 과거 → 현재 → 미래

모든 주제를 세 시점으로 나눠 조사한다. 기사만 보거나 데이터만 보지 않는다. **기사와 데이터를 항상 같이 본다.**

### 2-1. 과거 (최근 1개월)
- **데이터**: 아래 스니펫으로 3개월 일봉을 받아 다음을 직접 계산한다.
  - 1개월 전 / 1주 전 / 전일 / 최근 종가, 각각 대비 변화율
  - "연초 대비"는 **전년 마지막 거래일 종가** 기준으로 계산한다 (올해 첫 거래일 종가가 아님)
  - "52주 고점·저점"은 금융 사이트 표기와 같게 **장중 고가·저가** 기준으로 쓰고(일봉의 high·low), 검증 노트에 기준을 적는다
  - 최근 1개월 고점·저점과 그 날짜
- **기사**: 최근 1개월 기사를 날짜별로 찾아 주요 사건 3~5개를 고른다.
- **대조**: 각 사건 날짜 전후의 실제 시세 반응을 확인한다. 기사에서 "A 때문에 올랐다"고 했는데 그날 시세가 안 움직였으면 그 사건은 원인으로 쓰지 않는다.
- 결과를 날짜순 타임라인으로 정리한다.

### 2-2. 현재 (최근 1~3일)
- 오늘 이야기할 움직임의 원인을 최근 기사 2곳 이상에서 찾고, 그날의 시세 변화로 확인한다.
- 한 달 흐름 안에서 지금 위치를 판단한다: 고점 근처인지, 저점 근처인지, 추세가 바뀌었는지, 숫자로 말한다.

### 2-3. 미래 (앞으로 1~4주)
- **예정된 일정**: 실적 발표일, FOMC·BOJ·한국은행 금통위, CPI·고용 지표, 배당락일·분배일, 상장일 등. 공식 일정 또는 출처 2곳으로 날짜를 확인한다.
- **전망**: 애널리스트 목표가·컨센서스·기관 전망을 출처와 함께 모은다. 출처가 서로 다르면 범위로 쓴다.
- 단정하지 않는다. 강세 / 기본 / 약세 시나리오와, 어느 쪽인지 알려줄 확인 지표로 쓴다.
- 예측은 반드시 "전망", "예정", "~라면"으로 표시한다. 사실처럼 쓰지 않는다.

### 시세 확인 스니펫
```
node -e "(async()=>{const s='심볼',r='3mo';const q=(await (await fetch('https://query1.finance.yahoo.com/v8/finance/chart/'+encodeURIComponent(s)+'?range='+r+'&interval=1d',{headers:{'User-Agent':'Mozilla/5.0'}})).json()).chart.result[0];console.log('live',q.meta.regularMarketPrice);q.timestamp.forEach((t,i)=>console.log(new Date(t*1000).toISOString().slice(0,10),q.indicators.quote[0].close[i]))})()"
```
- 심볼: 미국 주식 티커(NVDA), KRW=X(원/달러), JPY=X(엔/달러), DX-Y.NYB(달러인덱스), ^TNX(미 10년물), CL=F(WTI), GC=F(금), BTC-USD, ^GSPC, ^IXIC, ^KS11
- 마지막 날 종가가 비어 있으면 live 가 현재가다. 장중 등락률과 종가 등락률을 섞지 않는다.
- 네트워크가 막혀 데이터를 못 받으면: 그 사실을 검증 노트에 적고, 숫자·방향은 기사 2곳이 일치할 때만 쓴다.

## 3. 교차검증 규칙

1. **숫자**: 기사 2곳, 또는 기사 1곳 + 시세 데이터로 확인된 것만 쓴다.
2. **방향 단어**(강세·약세·상승·하락·급등·급락·최고·최저·~만에): 반드시 시세 데이터로 확인한다. 기사와 데이터가 다르면 데이터를 따른다.
3. **환율 방향 주의**: 숫자 방향과 통화 강약이 반대다.
   - KRW=X 숫자 ↓ = 원화 강세, ↑ = 원화 약세
   - JPY=X 숫자 ↓ = 엔화 강세, ↑ = 엔화 약세
   - 원화·엔화·달러를 말할 때마다 해당 심볼로 지금 방향을 확인한다.
4. **원인 주장**: (a) 그 날짜의 기사와 (b) 그 날짜의 시세 반응이 둘 다 맞아야 "원인"으로 쓴다. 한쪽만 맞으면 "~라는 분석도 있어요"로 낮추거나 뺀다.
5. **지난 기사의 주장**: 1개월 안의 기사라도, 그 주장이 지금 데이터에서도 유효한지 다시 확인한다. 그 시점의 사실로만 쓸 때는 날짜를 붙인다. 예: "9/6엔 엔화가 강했지만, 지금은 157엔대로 다시 약해졌어요"
6. **기사끼리 충돌**: 데이터와 맞는 쪽을 쓴다. 데이터로 판단이 안 되면 두 견해를 같이 쓰거나 뺀다.
7. **같은 날 카드끼리** 서로 모순되는 내용이 없어야 한다.
8. 숫자나 사건은 절대 지어내지 않는다. 확인이 안 되면 쓰지 않는다.

## 5. 카드 구성: 과거 → 현재 → 미래

slides 는 4~5장이다. 각 장에 `phase` 를 붙여 시점을 표시한다. 기본 흐름은 다음과 같다(종목·돈의 흐름).

1. `"phase": "현재"`: 무슨 일이 있었나 (body + bullets)
2. `"phase": "과거 · 최근 한 달"`: `timeline` 3~5개, 마지막 항목에 `"now": true`
3. `"phase": "원인 분석"`: 왜 움직였나. 3장 규칙 4번을 통과한 원인만
4. `"phase": "미래 · 앞으로 2~4주"`: `timeline` 으로 예정 일정 2~4개
5. `"phase": "시나리오"`: 강세 / 기본 / 약세 + 확인 지표 (bullets), 또는 `big` 숫자 하나

ETF 는 이렇게 맞춘다: 현재(무엇을 담나, 비교표 `table`) → 과거(최근 1개월 수익률·자금 흐름) → 미래(분배일·리밸런싱·이벤트 일정) → 어떤 사람에게 맞는 구조인가.

### card.json 스키마 (`content/DATE/0N_이름/card.json`, 폴더명은 영문 대문자·숫자·_)

### 문장 규칙
- 쉬운 한국어 '~요' 체, 짧은 문장. 길이 제한을 지킨다. 넘치면 카드에서 글자가 잘린다.
- AI 티 나는 상투어("~의 모든 것", "완벽 정리", "알아보겠습니다", "주목할 필요가 있습니다")와 과한 이모지는 쓰지 않는다.
- 매수·매도 권유("사세요", "무조건 오른다")는 쓰지 않는다. 시나리오와 체크포인트로만 쓴다.

## 7. 환율 전망 (outlook/fx.json) — 하루 3번 갱신용

앱의 '환율' 탭에 보이는 전망이다. 카드뉴스와 같은 원칙(과거→현재→미래, 기사×데이터 교차검증)을 따른다.

### 조사 순서
1. **데이터**: KRW=X, JPYKRW=X(×100 = 원/100엔), EURKRW=X, JPY=X, DX-Y.NYB 의 3개월 일봉과 오늘 5분봉을 받아 현재가·전일 대비·1주·1개월 변화·1개월 고저를 계산한다.
   `node _system/fetch_live.js` 를 실행하면 `live/fx.json` 에 이 값들이 계산되어 나온다(이 파일은 커밋하지 않는다).
2. **과거(1개월)**: 큰 움직임이 있던 날의 원인을 기사에서 찾고, 그날 시세로 맞는지 확인한다.
3. **현재(최근 1~2일)**: 오늘의 환율을 움직인 요인을 국내 외환 기사(마감 시황, 외환브리핑) 2곳 이상에서 확인한다.
4. **미래(1~4주)**: 미국 CPI·고용, FOMC, ECB, BOJ, 한국은행 금통위 등 일정을 공식 일정 또는 출처 2곳으로 확인한다. 확인 안 되면 넣지 않는다.

### 전망 작성 원칙
- `view`: 앞으로 1주 동안 환율 숫자가 내려갈 쪽이 우세하면 "down", 오를 쪽이면 "up", 근거가 팽팽하면 "neutral". 근거가 부족하면 반드시 "neutral".
- `confidence`: "낮음" / "보통" / "높음". 상승·하락 요인이 엇갈리거나 큰 일정(CPI·FOMC)이 1주 안에 있으면 "높음"을 쓰지 않는다.
- `range`: 앞으로 1주 예상 범위 [하단, 상단]. 최근 1개월 고저와 기사 속 예상 레인지를 근거로 정하고, 현재가가 범위 안에 있어야 한다.
- `drivers`: 각 요인은 `effect`("up" = 환율 숫자를 올리는 요인, "down" = 내리는 요인), 짧은 설명, 출처(매체·날짜), url. 출처 1곳뿐이면 src 에 "1곳"을 적고 '가능성'으로 표현한다.
- `scenarios`: 하락 / 기본 / 상승 3개. 각 조건(무엇이 일어나면)과 예상 구간.
- 확률(%)이나 목표가를 단정하지 않는다. "참고용 전망"이다.
- 방향 표현은 3장 규칙 3번(환율 방향 주의)을 반드시 지킨다.

### 형식 (outlook/fx.json)
```

  "headline": "한 줄 제목 (20자 이내)",
  "summary": "2문장 요약",
  "pairs": [
    {"code": "USDKRW", "name": "원/달러", "label": "1달러",
     "view": "down|up|neutral", "viewText": "박스권 (중립) / 원화 강세 우위 / 엔화 약세 우위 등", "confidence": "보통",
     "base": 1343.6, "baseNote": "10/6 서울 종가", "range": [1330, 1360], "rangeNote": "앞으로 1주 예상 범위",
```

## 8. 종목 분석 (analysis/<심볼>.json) — 앱 '분석' 탭

사용자가 앱에서 종목을 요청하면, 펀드매니저가 투자위원회에 올리는 보고서처럼 그 회사를 평가한다.
**매수·매도 지시("사세요", "파세요")는 쓰지 않는다.** 대신 근거가 있는 종합 평가(점수, 긍정·중립·부정)와, 판단을 바꿀 조건을 쓴다. 최종 판단은 사용자 몫이다.

### 8-1. 요청 찾기
- 요청은 GitHub 이슈다. `curl -s "https://api.github.com/repos/baekseungchang/cardnews/issues?state=open&creator=baekseungchang&per_page=30"` 에서 제목이 `[분석]` 으로 시작하는 것만 처리한다(다른 사람이 연 이슈는 무시).
- 제목의 `[분석]` 뒤가 요청어다(티커 또는 회사명, 한글 가능). 한 번 실행에 최대 3개까지, 오래된 것부터 처리한다.
- 심볼 찾기: 한글 이름이면 영문 회사명으로 바꿔 `https://query1.finance.yahoo.com/v1/finance/search?q=영문이름&quotesCount=5` 로 찾는다. 한국 주식은 `005930.KS`(코스피), `.KQ`(코스닥) 형식. 상장 주식(EQUITY) 또는 ETF만 다룬다. 찾을 수 없으면 아래 8-6의 `notFound` 형식 파일을 만든다.

### 8-2. 데이터 (직접 계산)
- 클라우드 환경에서 야후 시세 서버가 막히면(403) 가격·차트는 기사·금융 사이트에서 확인한 값으로 채우거나 비워 둔다. **빌드(GitHub)가 `price`·`chart` 를 실제 시세로 자동 보정한다.** 그래서 본문(thesis·scores 등)에는 가격 숫자보다 재무·사건 근거를 중심으로 쓰고, 가격을 쓸 때는 날짜를 붙인다.
- 1년 주봉: `range=1y&interval=1wk` → `chart` 배열(종가 52개 안팎)
- 일봉 3개월: 1개월·3개월 변화, 1개월 고저
- 계산: 현재가(최근 종가), 1개월·3개월·연초 대비·1년 변화율, 52주 고점·저점(장중 고가·저가 기준)
- 재무 지표(매출, 영업이익률, 순이익, 잉여현금흐름, 현금·부채, PER·PSR 등)는 공식 실적 발표·IR 자료·stockanalysis.com·재무 데이터 사이트에서 찾고, **두 곳에서 확인되면** 쓴다. 기준 분기·연도를 꼭 적는다.

### 8-3. 과거 → 현재 → 미래
- **과거 (최근 1년, 특히 1개월)**: 큰 주가 변동이 있던 날 3~5개와 그 원인. 원인은 그날 기사 + 그날 시세 반응으로 확인(3장 4번).
- **현재 (최근 1~2주)**: 최근 실적, 가이던스, 신제품·계약·규제 이슈. 발행일 확인.
- **미래 (앞으로 1~3개월)**: 실적 발표일, 제품 행사, 규제 결정 등 일정(출처 2곳). 애널리스트 컨센서스·목표가는 출처와 발표 날짜가 있는 것만, 범위로.

### 8-4. 점수표 (각 1~5점, 이유 한 줄 + 근거)
| key | 항목 | 5점에 가까운 경우 | 가중치 |
|---|---|---|---|
| growth | 성장성 | 매출·이익이 빠르게 늘고 가이던스도 상향 | 25 |
| profit | 수익성 | 마진이 높고 개선 중 | 15 |
| balance | 재무 안정성 | 현금 많고 부채 적고 잉여현금흐름 플러스 | 15 |
| value | 밸류에이션 | 성장 대비 싸다 (과거·경쟁사 대비) | 20 |
| momentum | 모멘텀 | 주가 추세와 뉴스 흐름이 좋다 | 15 |
| risk | 리스크 | 리스크가 작다 (점수가 높을수록 안전) | 10 |
- 종합 점수 = Σ(점수 × 가중치) ÷ 5 (0~100, 반올림)
- 판단: 65 이상 `positive`("긍정적"), 45~64 `neutral`("중립"), 44 이하 `negative`("부정적")
- 확신도: 재무·뉴스 근거가 충분하면 "보통", 부족하거나 큰 이벤트가 2주 안에 있으면 "낮음". "높음"은 거의 쓰지 않는다.
- 점수는 근거로만 정한다. 근거가 부족한 항목은 3점(중간)으로 두고 이유에 "자료 부족"이라고 쓴다.

### 8-5. 펀드매니저 관점으로 쓸 것
- `thesis`: 핵심 투자 논지 2문장 (무엇이 좋아지고, 무엇이 걸림돌인가)
- `bull` / `bear`: 강세 논리 3개, 약세 논리 3개. 각각 근거 숫자 포함
- `scenarios`: 강세·기본·약세. 각각 "무엇이 일어나면 → 어떻게 될 수 있나". 자체 목표가는 만들지 않는다
- `watch`: 판단을 바꿀 체크포인트 3~4개 ("~가 확인되면 긍정 쪽", "~면 부정 쪽")
- 쉬운 한국어 '~요' 체. 숫자는 구체적으로. 과장·확신 표현 금지

### 8-6. 형식 (analysis/<심볼에서 . 을 _ 로 바꾼 이름>.json, 예: TSLA.json, 005930_KS.json)
```
{
  "symbol": "TSLA", "query": "테슬라", "name": "테슬라", "nameEn": "Tesla, Inc.",
  "market": "NASDAQ", "sector": "전기차·AI", "currency": "USD",
  "updated": "2026-10-07T10:30:00+09:00",
  "issue": 12,                                  // 처리한 이슈 번호
  "price": {"last": 378.73, "asOf": "10/5 종가", "chg1m": 0.6, "chg3m": -9.8, "chgYtd": -13.5, "chg1y": 12.3, "high52": 488.5, "low52": 214.3},
  "chart": [52개 안팎의 주간 종가],
  "assessment": {"score": 58, "stance": "neutral", "stanceText": "중립", "confidence": "보통",
                 "thesis": "2문장"},
  "scores": [{"key": "growth", "name": "성장성", "score": 3, "reason": "한 줄", "src": "매체 (날짜)"}, ... 6개],
  "fundamentals": [{"label": "매출 (2분기)", "value": "$22.5B", "note": "전년 대비 -12%", "src": "회사 실적발표 (7/22)"}],   // 4~8개
```

## 9. 기억과 복기 (학습 루프) — 모든 작업 공통

AI 모델 자체를 다시 학습시킬 수는 없다. 대신 **검증된 사실을 쌓고, 지난 전망을 채점해서, 다음 판단에 반영**한다.

### 9-1. 작업 전에 읽기
- `knowledge/log.jsonl`: 최근 30일의 검증된 사실 메모. 같은 주제를 다룰 때 이어지는 흐름(예: "9/18 BOJ 1.25%로 인상")을 활용하고, 지난 사실과 모순되는 새 주장은 다시 확인한다.
- `knowledge/fx-track.json` (환율 전망 작업일 때): `stats`(1주 뒤 범위·방향 적중 수)와 `recentMisses`(빗나간 전망). 빗나간 패턴이 있으면(예: 범위를 너무 좁게 잡음, 방향을 자주 틀림) 이번 전망에 반영하고, 반영한 내용을 `method` 에 한 문장으로 적는다. 채점은 GitHub가 실제 시세로 자동으로 한다(직접 채점하지 않는다).

### 9-2. 작업 뒤에 쓰기
- 이번 작업에서 **교차검증을 통과한 사실**만 3~8줄 골라 `knowledge/log.jsonl` 끝에 한 줄씩 덧붙인다(기존 줄은 지우거나 고치지 않는다):
  `{"date":"2026-10-07","topic":"USDKRW","fact":"10/6 원·달러 서울 종가 1,343.6원, 한 달 만의 최저","source":"머니투데이·베타뉴스 (10/6)"}`
- topic 은 티커·통화코드·주제어(예: "BOJ", "FOMC", "TSLA").
- 예측·의견은 쓰지 않는다. 사실만 쓴다.
- 이 파일은 git 에 함께 커밋한다(`git add knowledge/log.jsonl`). 30일이 지난 줄은 빌드가 `knowledge/archive/` 로 옮겨 영구 보관한다(지우지 않음).

## 10. 뉴스 감시 (news/feed.json) — 3시간마다

새 뉴스가 나오면 확인·분석해서 앱의 '뉴스' 탭에 올리고, 검증된 사실은 기억(9장)에 쌓는다.

### 10-1. 무엇을 찾나
- 최근 3~6시간 안에 나온 **시장을 움직일 만한 뉴스**: 미국·한국 주요 종목(실적, 가이던스, 인수합병, 규제, 대형 계약), 금리·환율·유가, 중앙은행 발언·결정, 주요 경제지표.
- `analysis/index.json` 에 있는 종목(사용자가 관심 있는 종목)과 최근 카드 주제의 새 소식은 꼭 찾아본다.
- 이미 `news/feed.json` 에 있는 뉴스(같은 사건)는 다시 올리지 않는다. 같은 사건에 중요한 후속 소식이 있으면 새 항목으로 올리고 앞 소식을 언급한다.

### 10-2. 검증
- 발행 시각을 확인한다. 같은 사실을 **출처 2곳**에서 확인한다. 1곳뿐이면 `"confidence": "주의"` 로 표시하고 단정하지 않는다.
- 숫자(주가 등락, 실적 수치)는 기사 2곳 또는 금융 사이트로 확인한다. 루머·SNS 단독 주장은 올리지 않는다.
- 3장 교차검증 규칙(방향 단어, 환율 방향 주의)을 그대로 지킨다.

### 10-3. 분석
- 각 뉴스마다: 무슨 일인지(2문장), 왜 중요한지, 누구에게 어떤 영향이 갈 수 있는지(관련 종목·통화).
- 영향은 `"dir": "up" | "down" | "neutral"` (관련 자산 가격에 대한 방향) + 한 줄 설명. 확신이 없으면 neutral.
- 매수·매도 지시는 쓰지 않는다.

### 10-4. 형식 (news/feed.json) — 새 항목을 맨 앞에 넣고, 최신 80개만 남긴다
```
{
  "updated": "2026-10-07T09:40:00+09:00",
  "items": [
    {"id": "20261007-0940-1", "time": "2026-10-07T09:10:00+09:00",
     "category": "종목 | 환율 | 금리 | 원자재 | 정책 | 국내 | 지표",
     "title": "짧은 제목 (25자 이내)",
     "summary": "무슨 일인지 2문장",
     "why": "왜 중요한지 1문장",
     "impact": {"dir": "up", "text": "관련 자산에 어떤 영향이 갈 수 있는지 1문장"},
     "tickers": ["TSLA"],
     "confidence": "확인 | 주의",
     "sources": [{"name": "매체 (10/7 09:05)", "url": "https://..."}]}
  ]
}
```
- 새로 올릴 만한 뉴스가 없으면 아무것도 바꾸지 않고 끝낸다(빈 push 금지).
- 올린 뉴스 중 검증된 사실은 9-2에 따라 `knowledge/log.jsonl` 에 덧붙인다.

## 11. 기억 범위 (9장 보충)
- `knowledge/log.jsonl` 은 최근 30일, 그 이전 사실은 `knowledge/archive/YYYY-MM.jsonl` 에 **영구 보관**된다(빌드가 자동으로 옮김). 특정 주제의 오래된 흐름이 필요하면 `grep -h '"topic":"TSLA"' knowledge/archive/*.jsonl` 처럼 찾아 쓴다.
- `knowledge/analysis-history.jsonl`: 지금까지의 모든 종목 분석 요약(점수·판단·당시 가격). `knowledge/analysis-track.json`: 30일 뒤 실제 주가로 채점한 결과(시장 지수 대비). 같은 종목을 다시 분석할 때 이전 판단과 그 결과를 반드시 확인하고, 빗나갔다면 무엇을 놓쳤는지 thesis 에 반영한다.
